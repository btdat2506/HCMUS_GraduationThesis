# Control Bus Peripherals Implementation

This document provides a comprehensive analysis of the Control Bus peripherals implemented in the RISC-V RocketChip SoC, including BootROM, CLINT (Core Local Interruptor), PLIC (Platform-Level Interrupt Controller), and Debug Unit. These peripherals are generated from Chisel/Scala descriptions and connected to the RocketChip's control bus infrastructure.

## Overview

The Control Bus peripherals represent the core system management and debugging infrastructure of the RISC-V SoC. Unlike the PeripheryBus devices which are external hardware IP blocks, these peripherals are generated directly from the RocketChip generator and provide essential services for:

- **Boot Process Management**: BootROM provides initial firmware and device tree
- **Core-local Interrupt Handling**: CLINT manages timer and software interrupts
- **System-wide Interrupt Control**: PLIC routes external interrupts to processor cores
- **Debug and Test Access**: Debug Unit enables JTAG-based debugging and system bus access

## Architecture Overview

### Bus Hierarchy

The Control Bus peripherals connect to RocketChip through the TileLink protocol in a dedicated control address space separate from the main system buses:

```
RocketChip Core Complex
├── ControlBus (TileLink)
│   ├── BootROM (Device Tree + Initial Firmware)
│   ├── CLINT (Timer + Software Interrupts)
│   ├── PLIC (External Interrupt Controller)
│   └── Debug Unit (JTAG + System Bus Access)
├── PeripheryBus (TileLink → AXI4) 
└── MemoryBus (AXI4)
```

### Configuration Implementation

The Control Bus peripherals are configured through RocketChip's configuration system in `src/main/scala/rocket.scala`:

```scala
class RocketBaseConfig extends Config(

```

## BootROM Implementation

### Hardware Architecture

The BootROM is implemented as a TileLink read-only memory device generated by the `HasPeripheryBootROM` trait. It provides:

- **Memory-mapped ROM**: Fixed address space containing bootloader and device tree
- **Device Tree Storage**: Complete hardware description for software initialization
- **Boot Sequence Control**: Initial firmware executed on system reset

### Configuration Parameters

```scala
// From configuration
new WithBootROMFile("workspace/bootrom.img") ++
new WithDTS("freechips,rocketchip-vivado", Nil) ++
```

The BootROM configuration specifies:
- **Image Source**: `workspace/bootrom.img` containing compiled bootloader
- **Device Tree Compatibility**: `freechips,rocketchip-vivado` identifier
- **Address Space**: Mapped to processor reset vector location

### Implementation Details

**BootROM Generation Process:**
1. **Device Tree Compilation**: System device tree is generated based on RocketChip configuration
2. **Bootloader Assembly**: Custom bootloader with SD card boot support
3. **Image Creation**: Combined bootloader and device tree binary
4. **Hardware Integration**: ROM contents embedded in generated Verilog

**Boot Sequence:**
1. **Reset Vector**: CPU starts execution from BootROM base address
2. **Hardware Initialization**: BootROM code configures basic system components
3. **Device Tree Parsing**: Software discovers system configuration
4. **Secondary Boot**: Bootloader loads main firmware from SD card

### Memory Layout

The BootROM occupies a fixed region in the processor's address space, typically mapped at the reset vector location. The exact address depends on RocketChip configuration but follows RISC-V standard conventions.

## CLINT (Core Local Interruptor) Implementation

### Hardware Architecture

The CLINT provides machine-mode timer and software interrupts for RISC-V processor cores. It implements the RISC-V privileged specification requirements for:

- **Machine Timer (mtime)**: 64-bit real-time counter
- **Timer Compare (mtimecmp)**: Per-hart timer comparison registers  
- **Software Interrupts (msip)**: Inter-processor interrupt mechanism

### Configuration Parameters

```scala
// Implicit in BaseConfig through CLINTKey
case CLINTKey => Some(CLINTParams())
```

The CLINT is automatically included in RocketChip configurations and provides:
- **Timer Frequency**: Configurable timebase (typically 1MHz as set by `WithTimebase`)
- **Hart Support**: Scales with number of processor cores
- **Interrupt Routing**: Direct connection to core interrupt inputs

### Register Interface

**CLINT Register Map:**
- **msip (0x0000 + 4*hartid)**: Machine Software Interrupt Pending
- **mtimecmp (0x4000 + 8*hartid)**: Machine Timer Compare
- **mtime (0xBFF8)**: Machine Time Register

**Programming Model:**
```c
// Timer interrupt setup
volatile uint64_t *mtime = (uint64_t*)CLINT_BASE + 0xBFF8;
volatile uint64_t *mtimecmp = (uint64_t*)CLINT_BASE + 0x4000;
*mtimecmp = *mtime + timer_interval;

// Software interrupt trigger
volatile uint32_t *msip = (uint32_t*)CLINT_BASE;
*msip = 1; // Trigger software interrupt on hart 0
```

### Integration with RocketChip

The CLINT integrates directly with RocketChip cores through:
- **TileLink Interface**: Memory-mapped register access
- **Interrupt Lines**: Direct connection to core machine-mode interrupt inputs
- **Clock Domain**: Synchronous with system clock, timebase derived from configuration

## PLIC (Platform-Level Interrupt Controller) Implementation

### Hardware Architecture

The PLIC manages external interrupt sources and routes them to processor harts according to priority and enable settings. It implements:

- **Interrupt Gateway**: Configurable edge/level trigger detection
- **Priority Management**: 32-level priority system per interrupt source
- **Context Management**: Separate interrupt contexts for M-mode and S-mode per hart
- **Claim/Complete Protocol**: Atomic interrupt servicing mechanism

### Configuration Parameters

```scala
// From configuration
new WithNExtTopInterrupts(8) ++
// Implicit PLIC configuration
case PLICKey => Some(PLICParams())
```

The PLIC configuration includes:
- **External Interrupts**: 8 top-level interrupt inputs
- **Priority Levels**: 32 priority levels (0 = never interrupt, 1-31 = increasing priority)
- **Context Support**: Machine and Supervisor mode contexts per hart

### Register Interface

**PLIC Register Map:**
- **Source Priority (0x000000)**: Priority registers for interrupt sources
- **Interrupt Pending (0x001000)**: Pending interrupt status
- **Interrupt Enable (0x002000 + 0x80*context)**: Per-context enable bits
- **Priority Threshold (0x200000 + 0x1000*context)**: Minimum priority for context
- **Claim/Complete (0x200004 + 0x1000*context)**: Claim and completion interface

**Programming Model:**
```c
// Configure interrupt source priority
plic_base[source_id] = priority; // 1-31

// Enable interrupt for M-mode context
plic_base[0x2000/4 + context*0x20 + source_id/32] |= (1 << (source_id % 32));

// Set priority threshold
plic_base[0x200000/4 + context*0x400] = threshold;

// Claim interrupt (returns source ID or 0)
int source = plic_base[0x200004/4 + context*0x400];

// Complete interrupt handling
plic_base[0x200004/4 + context*0x400] = source;
```

### Integration with RocketChip

The PLIC connects to the RocketChip through:
- **TileLink Interface**: Memory-mapped register access via ControlBus
- **Interrupt Sources**: External interrupt inputs from PeripheryBus devices
- **Interrupt Outputs**: Connections to core external interrupt inputs
- **Multi-Hart Support**: Scalable to multiple processor cores

## Debug Unit Implementation

### Hardware Architecture

The Debug Unit provides JTAG-based debugging capabilities and system bus access according to the RISC-V Debug Specification. It includes:

- **Debug Transport Module (DTM)**: JTAG interface and protocol conversion
- **Debug Module (DM)**: Core debug functionality and hart control
- **System Bus Access**: Direct memory and peripheral access for debuggers
- **Program Buffer**: Small memory for executing debug operations

### Configuration Parameters

```scala
// Debug configuration
new WithDebugSBA ++
// With JTAG support (optional)
new WithJtagDTM ++
```

The debug configuration enables:
- **System Bus Access (SBA)**: Direct memory/peripheral access from debugger
- **JTAG DTM**: Hardware JTAG interface for debug probe connection
- **Program Buffer**: Execution environment for debug operations
- **Hart Control**: Halt/resume, single step, reset control

### Debug Module Features

**Core Debugging Capabilities:**
- **Hart Control**: Halt, resume, single-step execution
- **Register Access**: Read/write hart registers and CSRs
- **Memory Access**: Debug-mode memory operations
- **Breakpoint Support**: Hardware and software breakpoints
- **Program Buffer**: Execute arbitrary instructions in debug mode

**System Bus Access:**
- **Direct Memory Access**: Debugger can read/write system memory
- **Peripheral Access**: Access to memory-mapped peripherals
- **Bus Monitoring**: Observe system bus transactions
- **Non-intrusive Operation**: Minimal impact on system execution

### JTAG Interface

When configured with `WithJtagDTM`, the debug unit exposes a standard JTAG interface:

**JTAG Signals:**
- **TCK**: Test Clock
- **TMS**: Test Mode Select  
- **TDI**: Test Data Input
- **TDO**: Test Data Output
- **TRST**: Test Reset (optional)

**JTAG Chain:**
- **IDCODE**: 32-bit device identification
- **DTM Control**: Debug transport module control
- **DMI Access**: Debug module interface access

### Integration with RocketChip

The Debug Unit integrates with RocketChip through:
- **TileLink Interface**: System bus access via dedicated debug master port
- **Hart Interfaces**: Direct connections to processor debug interfaces
- **Reset Control**: System and hart reset capabilities
- **Clock Domains**: Operates in debug clock domain, independent of system clock

## Software Integration

### Device Tree Integration

All Control Bus peripherals are described in the device tree generated with the BootROM:

```dts
// CLINT node
clint@2000000 {
    compatible = "riscv,clint0";
    reg = <0x0 0x2000000 0x0 0x10000>;
    interrupts-extended = <&cpu0_intc 3 &cpu0_intc 7>;
};

// PLIC node  
plic@c000000 {
    compatible = "riscv,plic0";
    reg = <0x0 0xc000000 0x0 0x4000000>;
    interrupts-extended = <&cpu0_intc 11>;
    interrupt-controller;
    #interrupt-cells = <1>;
};
```

### Linux Kernel Support

The Linux kernel includes drivers for all Control Bus peripherals:
- **CLINT Driver**: `drivers/clocksource/timer-clint.c`
- **PLIC Driver**: `drivers/irqchip/irq-riscv-intc.c` and `drivers/irqchip/irq-sifive-plic.c`
- **Debug Support**: Integrated with Linux debug infrastructure

### Firmware Integration

OpenSBI (RISC-V Supervisor Binary Interface) provides M-mode firmware support:
- **CLINT Management**: Timer and IPI handling
- **PLIC Configuration**: Interrupt routing setup
- **Debug Support**: Debug module management in M-mode
